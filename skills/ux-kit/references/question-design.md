# 题型库与问卷设计最佳实践

## 一、常见题型及使用场景
### 1.1 单选题
**适用**：互斥选项，只能选一个
**示例**：
> 您最常使用哪个功能？
> □ 功能A □ 功能B □ 功能C □ 其他

### 1.2 多选题
**适用**：可多选，选项不互斥
**示例**：
> 您使用过以下哪些功能？（可多选）
> □ 功能A □ 功能B □ 功能C

### 1.3 李克特量表 (Likert Scale)
**适用**：测量态度/同意程度

常用级数：
- **5 级**：非常不同意 / 不同意 / 一般 / 同意 / 非常同意
- **7 级**：非常不同意 / 不同意 / 比较不同意 / 一般 / 比较同意 / 同意 / 非常同意

设计要点：
- 保持正负方向平衡
- 标签间距尽量等距（视为定距数据）
- 避免过多中性选项导致趋中效应

### 1.4 语义差异量表
**适用**：测量用户对某个概念的感知
**示例**：
> 请对产品界面风格进行评价：
> 传统的 □ □ □ □ □ 现代的
> 复杂的 □ □ □ □ □ 简洁的

### 1.5 排序题
**适用**：优先级/重要性排序
**示例**：
> 请按重要性从高到低排列以下因素（1=最重要）：

### 1.6 矩阵题
**适用**：多行×多列的组合题
**示例**：
> | 题目 | 非常同意 | 同意 | 一般 | 不同意 | 非常不同意 |
> |------|---------|------|------|--------|-----------|
> | 功能A好用 | □ | □ | □ | □ | □ |
> | 功能B好用 | □ | □ | □ | □ | □ |

### 1.7 开放题
**适用**：收集定性意见
**示例**：
> 您对产品还有什么建议？

### 1.8 NPS 题 (0-10分)
**适用**：衡量用户口碑推荐
**示例**：
> 您有多大可能向朋友推荐本产品？（0=完全不可能，10=非常有可能）

### 1.9 CSAT 题
**适用**：衡量单次交互/功能满意度
**示例**：
> 您对本次服务体验的满意度如何？
> □ 非常满意 □ 满意 □ 一般 □ 不满意 □ 非常不满意

### 1.10 配对多选题 (ETS模型用)
**适用**：同时测量维度的满意度和关注度
结构：同一维度两道题——满意度 + 关注度

## 二、问卷设计最佳实践
### 2.1 题目表述规范（正反示例）
| 规范 | 正确写法 | 错误写法 |
|------|---------|---------|
| **一题一问** | "界面布局清晰易读" | "界面布局和配色都很好看"（两个概念） |
| **具体可感知** | "能在我需要时快速找到目标功能" | "信息架构合理"（太抽象） |
| **中性表述** | "操作步骤数量是合理的" | "简化了操作流程，您是否感到满意？"（预设正面） |
| **避免否定嵌套** | "我能顺利完成目标" | "我不会因为找不到功能而卡住"（双重否定增加认知负担） |
| **不预设前提** | "遇到问题时能获得有效帮助" | "当产品崩溃时，恢复速度是否让您满意？"（假设负面场景） |

### 2.2 问题措辞原则
1. **简单明了**：使用目标用户能理解的语言
2. **具体而非抽象**：例如问"上周您使用了几次该功能"而不是"您经常使用该功能吗"
3. **避免双重重载**：不要将两个概念塞进一个问题
4. **避免引导性**：不暗示"应该"的答案
5. **避免假设性**：减少"如果您..."这类假设性问题
6. **避免否定句**：用户容易误解否定句式

### 2.3 选项设计原则
1. **互斥性**：选项之间不重叠
2. **穷尽性**：覆盖所有可能回答，无法穷尽时加"其他（请注明）"
3. **平衡性**：正负方向选项数量对称
4. **特异性**：标签具体明确，"经常"这类模糊词尽量给出量化定义

### 2.4 问卷结构原则
1. **漏斗顺序**：从宽泛到具体
2. **敏感问题置后**：收入、隐私等放在问卷后半段
3. **人口统计学放在最后**（甄别题除外）
4. **相似主题归组**：降低认知切换成本
5. **随机化选项顺序**（在工具条件允许时）：减少顺序偏差

### 2.5 信效度考量
- **引用成熟量表**时注明出处和信度系数（Cronbach's α）
- 自定义量表至少需要 3-5 题/维度
- 建议进行预测试（pilot test）以检查题项可理解性
- 需要时包含反向计分题以减少 acquiescence bias

## 三、题项展开与丰富化思路

以下思路作为生成问卷时的参考方向，非强制要求。根据研究目标和实际条件灵活选用。

### 3.1 分层下钻
问卷评估可以不止"维度→题目"一层平铺，而按层次逐级展开，每层为下一层提供下钻方向：

- **L0 行为锚定**：先了解用户的具体使用行为（用了哪些功能、参与哪些活动、什么场景下使用），为后续评价提供行为上下文
- **L1 总体评价**：一道总体满意度或NPS题
- **L2 维度矩阵**：3-4个核心维度的矩阵打分
- **L3 子维度展开**：对L2中需要细化的维度展开子项（如"易用性"→入口好找/界面合理/指引有效/反馈清晰/步骤简洁/防误操作）
- **L4 低分诊断**：针对可能低分的维度，在矩阵后追加1-2道"以下哪些方面存在问题"的多选题

> 跳转逻辑保持简单：L4诊断题不需要设条件跳转，直接作为矩阵后的常规题目出现，题目说明中注明"针对XX方面可能存在的问题"。问卷系统支持简单跳转时，可加内联标注；不支持时直接平铺即可。不必所有维度都下钻到L4，选择最关键的2-3个维度即可。

### 3.2 行为前置锚定
在满意度评价前，先设计1-2道行为盘点题（多选），让用户确认自己的具体使用情况。好处：
- 为后续评价提供行为上下文（区分"用过的人评的"和"没用过的人评的"）
- 行为本身是有价值的发现（哪些功能用得多、哪些少）
- 后续可作分组变量对比

示例：
> 请问您一般在平板上进行以下哪些类型的"多任务"活动？（可多选）
> - 同时使用A、B应用完成一件事（如：边看网课视频边记笔记）
> - 主用A应用时，临时使用B应用并快速回到A（如：看视频时临时回复消息）

### 3.3 低分诊断
在矩阵量表后追加诊断题，是提升问卷诊断价值的关键手段：

> 矩阵题（各维度/子维度打分）→ 诊断题（"以下哪些方面存在问题"多选）

诊断题的选项应具体可操作，指向可改进的点，而非笼统的"不好用"。选项设计可参考以下方向：
- 性能类：启动慢/卡顿/闪退/适配不足
- 操作类：入口深/步骤多/方式隐蔽/不符合预期/容易误触
- 功能类：方式单一/无法调整/数量不足/不支持某些场景
- 信息类：元素含义不明/布局不清/缺少指引

> 以上为选项设计参考方向，非固定模板，根据具体产品特征组织。

### 3.4 "不使用"原因参考
涉及功能采纳/使用情况时，可参考以下原因分类框架设计"不使用原因"题：

- **认知缺失**：完全不知道有此功能
- **认知未转化**：知道但不了解如何使用 / 知道但没有使用习惯
- **体验后放弃**：尝试过但操作难 / 尝试过但不满足需求 / 尝试过但体验差（bug/卡顿）

> 此框架覆盖"认知→尝试→持续使用"链路，可作为选项设计参考。实际使用时根据产品特点调整分类和措辞，不必照搬。

### 3.5 场景-功能匹配矩阵
当产品有多个功能/方案，需要了解各自适用场景时，可用场景×功能的匹配矩阵：

| 使用场景 | 功能A | 功能B | 都适合 | 都不适合 |
|---|---|---|---|---|
| 场景1（带具体示例） | | | | |
| 场景2（带具体示例） | | | | |

比逐个功能单独评价更高效，且能揭示"哪种场景该用哪个功能"的适配关系。

### 3.6 概念前置解释
评估特定功能或概念时（尤其B端或专业产品），可在正式题目前插入1-2段文本描述，解释核心概念并给出示例，确保被访者在同一理解下作答。文本描述题不计入分析，仅作概念对齐，非必答。

### 3.7 注意力检测（视情况）
当问卷较长（>30题）或线上投放、数据质量不可控时，可插入1道注意力检测题（如"请选择'同意'"或简单常识题）。问卷较短或面向内部用户时通常不需要。

### 3.8 行为意图/动机分类
在行为盘点中可加入动机分类题，如"有明确需求专门来用"vs"看到推荐/优惠顺便用了"。这类分组变量比纯人口统计更有解释力，可在分析时对比不同动机群体的体验差异。
