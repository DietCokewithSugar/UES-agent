# 跨源综合分析引擎

> 本文件为用户研究分析结论技能的参考模块，在Step 4执行跨数据源综合分析时读取使用。

## 核心任务

将多个数据源的独立分析结果打散重组，按研究主题组织，执行三角验证和言行矛盾检测，最终输出跨源主题结构。

## 按研究类型的综合调整

跨源综合的**聚类主线、综合重点、输出侧重**随研究类型变化。Step 1 确定研究类型后，先按下表调整再执行聚类；**含多类型时取各类型对应的综合侧重合并执行**，并在主题层面交叉整合（如竞品机会点 × 自身体验痛点 → 改版建议）：

| 研究类型 | 聚类主线 | 综合重点 | 输出侧重 |
|---------|---------|---------|---------|
| 客群研究 | 客群特征 / 场景 | 特征-行为-态度-需求-痛点链条 | 客群画像卡片、机会点清单 |
| 用户需求分析 | 需求及其成因 | 习惯/态度背后的深层原因 | 需求清单、设计/运营决策依据 |
| 竞品分析 | 对比维度 | 定位 / 功能 / 客群三线对比 | 差异点、趋势与机会点、借鉴建议 |
| 需求分析 | 需求类型与优先级 | 卡诺分类 + 重要程度 | 建设改造优先级排序 |
| 功能架构设计 | 用户心智分类 | 卡片分类结果与认知模型 | 功能架构建议、与现有架构差异 |
| 设计方案对比验证 | 方案 × 维度 | 各方案在不同维度的表现差异 | 偏好结论与内在原因、最佳方案 |
| 体验测试 | 体验问题与严重度 | 可用性 / ETS-E 表现 vs 上线标准 | 上线预备度结论、必须修复项 |
| 体验评估 | 体验维度 | 整体 + 分维度水平、声音与典型问题 | 评估结论与改进建议 |

**多类型综合的分析结论组织**：融合式时，各类型聚类主线合并，数据点统一聚类后按主题呈现；分块式时，先按类型各自聚类呈现，再在"行动建议"层交叉综合（详见 `references/analysis_template.md`）。

## 嵌入框架的挂接

跨源综合阶段除主题聚类外，还需按 Step 3 判定产出**结构化框架**（卡诺模型 / 用户画像 / 灵犀旅程 / 服务蓝图 / 心智模型 / JTBD 动机映射），执行时读取 `references/frameworks.md`：

- 框架的"分析步骤"直接依据综合后的证据执行；标"需要综合"的框架须在三角验证之后完成，确保用到多源一致的结论。
- 框架产出与主题聚类产出是互补的两类成果：主题回答"发现了什么"，框架回答"用什么结构呈现/验证"。两者都进入 Step 6 分析结论（框架作为可选模块）。
- 框架间允许交叉：如画像分群结论反向支撑卡诺分群差异、心智模型的任务塔可对齐旅程的行为层。

**对比型分析结论的特殊三角验证**（竞品分析、设计方案对比验证）：

- 此类分析结论的比较对象是**不同产品/方案**而非不同数据源，"数据源"维度变更为"比较对象"维度（方案A/方案B，或竞品X/竞品Y/自身）。
- 三角验证演化为两部分：
  1. **对象内部多方法交叉**：同一比较对象上多方法结论一致（如方案A在眼动+访谈+问卷中均表现更优）；
  2. **对象间差异显著性**：不同对象的关键指标差异是否显著、能否归因。
- 言行矛盾检测仍需执行（如方案A问卷偏好高，但眼动任务效率低，需解释偏好来自视觉吸引还是有效性）。
- 聚类时每个比较对象内部的发现先各自聚类，再横向对比"维度差"。

## 分析方法

### 一、亲和图聚类

**目的**：将按数据源组织的发现重组为按研究主题组织。

**步骤**：
1. 将各数据源"数据快照"中的每一条发现提取为独立数据点
2. 去除数据源标签，只保留发现内容和原始出处引用
3. 按语义亲和力聚类：含义相近、指向同一问题、描述同一现象的归为一组
4. 为每个聚类生成主题名称（简洁、有穿透力、反映核心问题）
5. 检查每个主题至少有两个独立数据点支撑

**聚类锚点**：
- 优先围绕用户在Step 1提供的研究目的和关键问题
- 允许出现"研究目标之外的新发现"主题（来自数据驱动）
- 主题粒度：太粗（如"用户体验问题"）→ 拆分；太细（如"按钮A的位置"）→ 归入上级主题

**输出**：
- 主题列表（名称 + 简要说明 + 包含的数据点数量）
- 每个主题下的数据点清单（含原始出处）

### 二、三角验证

**目的**：评估每个主题的置信度，识别多源一致与矛盾。

**验证流程**：

对每个主题，逐数据源检查：
1. 该数据源是否有与该主题相关的发现？
2. 如果有，发现的方向是什么？（正向/负向/中性）
3. 与其他数据源的方向是否一致？

**验证状态判定**（基础判定，先定"是否多源"）：

| 状态 | 条件 | 基础置信度 |
|------|------|--------|
| ✅ 收敛 | 2个及以上数据源方向一致 | **高** |
| ⚠️ 矛盾 | 不同数据源方向不一致 | **低**，需进一步分析 |
| ❓ 单源 | 仅1个数据源支撑 | 见下方"单源口径" |

**结论可信度五级定档**（高 / 中高 / 中 / 中低 / 低）：

| 级 | 定档依据（多源） | 定档依据（单源） |
|----|----------------|----------------|
| 高 | 2+ 源收敛，且结论影响面大、样本充分 | 不适用（单源永不为"高"） |
| 中高 | 2+ 源收敛，但样本量偏小/其中某源较薄 | 单源 + 方向一致 + 参与该结论的数据点数量充足（如问卷同级题 ≥30 或访谈 ≥6 人之一致表述）且无矛盾反例 |
| 中 | 多源部分收敛、部分缺失（非矛盾） | 单源 + 方向基本一致但样本偏少（如访谈 3-5 人），或数据点数量一般 |
| 中低 | 多源收敛但存在 1 处次要矛盾且已解释 | 单源 + 方向基本一致但样本明显不足（1-2 人），或数据点稀疏 |
| 低 | 多源矛盾未获合理解释 | 单源 + 样本不足 + 证据相互冲突 |

**单源口径（关键规则）**：

- 仅 1 个数据源时，**基础判定直接跳过"收敛/矛盾"判断**，改为按"**方向一致性 + 数据点数量**"定档（见上表单源列）。
- 单源结论**最高为中高，永不标"高"**（"高"保留给跨源收敛）。
- 单源 + 证据不足/样本极少 → 在可信度后**追加标注"证据有限"**（如"结论可信度：中低（证据有限，单源且样本少）"）。
- 判断"同源内方向一致"时：同一问卷中相关题组方向一致、同一访谈内多人表述一致才算"一致"；若同源内数据互相矛盾，按"低"处理。

**输出口径统一**：可信度最终在分析结论中以"高 / 中高 / 中 / 中低 / 低"五档呈现（SKILL Step 6 术语分离原则下，三角验证过程词不出现，只输出定档结果 + 括号依据）。

**言行矛盾检测**：

重点检测以下典型矛盾模式：
- 问卷说"满意" × 访谈说"其实很烦" → 态度与表述矛盾
- 埋点显示"跳出率高" × 问卷说"体验不错" → 行为与态度矛盾
- 可用性测试"任务失败率高" × 问卷SUS分不低 → 客观表现与主观评价矛盾

对每个矛盾点：
1. 记录矛盾的具体数据（哪份数据说了什么）
2. 生成"可能解释"假设（至少2个）：
   - 解释A：方法论原因（如问卷社会赞许性偏差）
   - 解释B：用户分群差异（如满意的是老用户，不满的是新用户）
   - 解释C：场景差异（如整体满意但某环节特别差）
3. 标注该矛盾的优先级（影响核心结论 vs 影响边缘结论）

**输出**：
- 每个主题的三角验证状态
- 言行矛盾点列表（含可能解释和优先级）

### 三、整理→探索→求证三步法

在亲和图聚类和三角验证过程中，遵循三步法防止分析偏差：

**Step A：整理**
- 筛选、排序、组织所有发现
- 排除数据杂音（如样本量不足的结论、明显异常值）
- 按重要程度初步排序

**Step B：探索**
- 深挖数据背后的含义，发现多种可能性
- 不急于验证预设假设，允许意外发现
- 对矛盾点不急于消解，先探索不同解释
- 尝试不同的主题组织方式，看哪种更有解释力

**Step C：求证**
- 对探索阶段形成的候选主题和洞察，用多源证据论证
- 检查是否有遗漏的反例
- 对矛盾点的解释，优先选择有数据支撑的

**关键约束**：很多人跳过"探索"直接"求证"，导致只验证预设假设而忽略意外发现。在执行中必须先充分探索再收敛求证。

### 四、同理心地图分析

**目的**：对每个核心主题，从用户视角梳理Says/Thinks/Does/Feels，发现所说与所做之间的gap。

**使用时机**：当三角验证检测到言行矛盾时，用同理心地图深入分析。

**四象限内容来源**：
- Says（说了什么）：访谈引言、问卷开放题回答
- Thinks（想了什么）：访谈中的暗示、犹豫、转折
- Does（做了什么）：埋点行为数据、可用性测试操作记录
- Feels（感受如何）：满意度评分、情绪表达、SUS/SEQ分数

**分析重点**：
- Says vs Does 的gap → 言行矛盾的深层原因
- Says vs Thinks 的gap → 用户没有说出口的需求
- Thinks vs Feels 的gap → 理性认知与情感体验的差异

**输出**：每个矛盾主题的同理心地图 + gap分析

## 洞察提炼规范

### 洞察分级标准

**L1 事实发现**：
- 数据直接呈现的现象
- 不含推断，可被原始数据直接验证
- 示例："注册流程平均耗时3.2分钟（N=45）"

**L2 深层洞察**：
- 现象背后的原因、模式或关联
- 基于数据但不限于数据本身，含合理的分析推断
- 必须标注推断依据
- 示例："注册耗时长的根源是身份验证步骤，用户在此平均停留1.8分钟且错误率达35%，结合访谈发现用户对OCR识别的准确度不满"

**L3 行动建议**：
- 基于洞察的具体改进方向
- 需标注建议类型和预期影响
- 需区分"有强数据支撑"和"需要进一步验证"
- 示例："优化身份验证流程，建议引入OCR自动识别替代手动输入（数据支撑强度：多源验证✅；预期影响：降低注册流失率）"

### 优先级评估

**主题优先级** = f(与研究目标相关度, 数据支撑强度, 影响面)

**行动建议优先级** = f(影响度, 置信度)

影响度 × 置信度矩阵：
| | 高置信度 | 低置信度 |
|------|---------|---------|
| 高影响 | 优先执行 | 先验证再执行 |
| 低影响 | 纳入长期规划 | 暂不处理 |

## 输出格式

完成跨源综合后，输出以下内容供Step 5审查：

```markdown
## 主题结构

### 主题1：[名称]
- 优先级：高/中/低
- 简要说明：[1-2句话]
- 三角验证状态：✅ 收敛 / ⚠️ 矛盾 / ❓ 单源
- 支撑证据：
  - 问卷：[关键数据点]
  - 访谈：[典型引用 + 来源]
  - 埋点：[行为数据]
  - 可用性：[任务表现]
  - 眼动：[注视数据]
- 洞察层级：L1/L2/L3
- 洞察内容：[具体洞察陈述]

### 主题2：[名称]
...

## 言行矛盾点

### 矛盾1：[描述]
- 数据A：[来源 + 内容]
- 数据B：[来源 + 内容]
- 可能解释：[解释A / 解释B]
- 优先级：[影响核心/影响边缘]
```
