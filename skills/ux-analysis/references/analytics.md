# 埋点数据分析引擎

> 本文件为用户研究分析结论技能的参考模块，在Step 3展示埋点分析方案和Step 4执行埋点分析时读取使用。

## 适用条件

当Step 2识别到埋点数据时激活。埋点数据的核心特征：**反映用户行为的量化数据**。

支持的数据格式：

| 格式 | 典型特征 | 分析方式 |
|------|---------|---------|
| 原始事件流 | 事件名+时间戳+用户ID，一行一条事件 | 从原始数据聚合后执行全部分析 |
| 已处理的聚合数据 | DAU/MAU表、转化率表、功能使用率表等 | 跳过聚合步骤，直接进入对比和趋势分析 |
| 漏斗数据 | 各步骤用户数/转化率 | 直接用于漏斗分析和流失定位 |
| 功能使用数据 | 各功能的使用人数/频次/时长 | 直接用于功能热度排序和交叉分析 |
| 留存数据 | 按日/周/月的留存率 | 直接用于留存曲线和流失分析 |

**处理指引**：
- 优先检查数据是"原始事件流"还是"已处理的聚合数据"
- 已处理数据：跳过对应的聚合计算，直接进入分析
- 原始事件流：需先聚合为指标再分析
- 数据不完整时（如只有漏斗数据无留存数据），只执行数据支撑的分析，不做推测

## 分析方案

### 1. 行为概览

**核心指标**：
- DAU/MAU（如有日期跨度）
- 平均会话时长
- 功能使用率（使用某功能的用户/活跃用户）
- 时间趋势（关键指标随时间的变化，如适用）

**输出**：核心指标卡片 + 时间趋势图（如有时间维度）

### 2. 漏斗分析

**漏斗识别**：
- 优先识别用户在Step 1提及的核心转化路径
- 如用户未指定，根据事件序列自动推断核心路径
- 常见路径模式：首页→搜索→详情→下单→支付 / 注册→激活→留存

**分析内容**：
- 各步骤转化率
- 整体转化率（首步到末步）
- 流失最严重的步骤识别
- 步骤间耗时分析

**输出**：漏斗图 + 各步骤转化率表

### 3. 行为路径

**分析内容**：
- 用户实际路径 vs 设计路径对比
- 常见偏离路径识别（用户走了设计之外的路线）
- 路径分流点（在哪一步用户走了不同的方向）

**输出**：路径对比图 + 偏离路径列表

### 4. 功能热度

**分析内容**：
- 各功能/页面的使用频率排序
- 功能使用与用户分群的交叉（哪类用户用了哪些功能）
- 高频功能 vs 低频功能识别
- 功能关联使用（用了A功能的用户还用了什么）

**输出**：功能热度排序表 + 分群交叉表

### 5. 留存分析（如数据支持）

**分析内容**：
- 新用户留存曲线（D1/D7/D30，如时间跨度足够）
- 功能级留存（用了某功能的用户是否持续使用）
- 流失用户特征（最后一次操作是什么）

**输出**：留存曲线图 + 流失特征摘要

## 与其他嵌入框架的衔接

埋点数据是行为侧的定量实证来源（详见 `references/frameworks.md`）：
- **灵犀旅程**：行为数据提供"旅程结构"中用户实际走过的步骤与转换环节的实测量化（停留、转化、流失所在的旅程节点），是旅程优化点定位的重要支撑；当 Step 3 判定产出灵犀旅程且本次含埋点数据时，其"行为层"优先用埋点实测填充。
- **服务蓝图**：埋点"用户实际路径 vs 设计路径"的数据可用于佐证前台操作环节的设计偏差与断点（前台断点往往先体现为行为漏斗的流失步骤）。
- 埋点**不直接**支撑卡诺、画像、心智模型（后两者需要主观态度/认知数据），不要硬套。

## 与其他数据源的交叉对照

| 埋点信号 | 对照数据 | 交叉判断 |
|---------|---------|---------|
| 漏斗流失步骤 | 问卷（该环节满意度/WTS） | 流失环节是否正是低满意度环节 → 因果关系线索 |
| 功能热度 | 问卷功能认知/NPS原因、用户声音提及 | 高频使用但低认知 → 入口与认知错位；低频但高诉求 → 未被发现的潜力功能 |
| 路径偏离 | 访谈"找不到/走弯路"表述 | 行为偏离与主观困扰是否一致 |
| 留存下滑 | 用户声音流失抱怨、问卷倦怠题 | 客观流失与主观原因是否收敛 |

**交叉验证的三角标注**：✅ 收敛 / ⚠️ 矛盾 / ❓ 单源，与 `references/synthesis.md` 的标注口径一致。
