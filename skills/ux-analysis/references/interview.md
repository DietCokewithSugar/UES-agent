# 访谈数据分析引擎

> 本文件为用户研究分析结论技能的参考模块，在Step 3展示访谈分析方案和Step 4执行访谈分析时读取使用。

## 适用条件

当Step 2识别到访谈数据时激活。访谈数据的核心特征：**围绕研究问题与用户进行的深度对话或系统性记录**。

支持的记录格式：

| 格式 | 典型特征 | 识别信号 |
|------|---------|---------|
| 录音转录稿（逐字稿） | 口语化长文本，含语气词、重复、停顿 | 频繁出现"嗯""就是""然后"，句子不完整，无格式化标记 |
| Q&A对话格式 | 问答交替，有明确的采访者/受访者角色标记 | "Q:/A:"、"主持人:/用户:"、"采访者:/受访者:"、"I:/R:" |
| 访谈笔记/记录 | 半结构化，研究者整理后的要点记录 | 要点式叙述，可能有"用户提到""反馈"等研究者视角标记 |
| Excel访谈记录表 | 行=受访者或问题，列=结构化字段 | 包含"受访者""问题""回答""备注"等列的表格 |
| Word文档 | 混合格式，可能含Q&A段落+研究者批注 | 有格式化的问答段落，或叙述体+批注 |
| 纯文本文件 | 无格式标记的叙述体或对话 | 连续文本，可能按受访者分段 |

**处理指引**：
- 转录稿：保留原始措辞用于引用，但编码时可略过语气词和重复
- 笔记/记录：注意区分"用户原话"和"研究者概括"，编码时优先采用用户原话
- Excel记录：将每条回答视为独立文本单元，按行编码
- 多格式混合：如有多个访谈文件格式不同，统一转换为文本后执行分析

## 分析方法：Braun & Clarke 主题分析六阶段

### Phase 1：数据熟悉

- 通读所有访谈记录
- 标记初步印象和值得关注的现象
- 记录研究者备忘（初步直觉、与Step 1研究目标的关联）

**注意**：不要跳过这步直接编码。熟悉数据是后续主题质量的根基。

### Phase 2：初始编码

**编码方式**：
- 语义层面编码（Semantic）：受访者明确说了什么
- 潜在层面编码（Latent）：暗示了什么、言外之意

**编码原则**：
- 贴近数据命名，不要用太抽象的标签
- 每个编码覆盖一个明确的意思单元（不要太宽）
- 允许一段文本有多个编码
- 保持开放，不要急于归入预设分类

**输出**：编码本（Codebook）
```
| 编码名 | 定义 | 示例引用 | 来源 |
|--------|------|---------|------|
| 操作困惑 | 用户在描述某功能时表现出不确定或迷茫 | "我也不知道这个按钮是干什么的" | P03 |
```

### Phase 3：生成候选主题

- 将相似编码聚类为候选主题
- 检查每个候选主题是否有足够数据支撑（至少2-3个独立来源）
- 识别跨受访者反复出现的模式
- 允许一个编码归属于多个候选主题

**关键约束**：主题不是编码的简单堆叠，而是对数据意义的概括。好的主题名应该能让人不看具体编码也能理解这个主题在说什么。

### Phase 4：审查与精炼主题

- 对照原始数据检查每个主题的适配度
- 合并重叠主题
- 拆分过宽主题（一个主题包含太多不同方向 → 拆分）
- 确保主题间互斥且整体对研究发现有一定的穷尽性
- 回到Phase 2的编码本，检查是否有编码未被任何主题覆盖

### Phase 5：定义与命名

- 为每个主题撰写核心叙事（1-3句话说明这个主题讲了什么故事）
- 为主题命名：简洁、有穿透力、反映核心问题
- 命名参考：
  - 好的主题名："身份验证成为注册的隐形门槛"
  - 差的主题名："注册问题"

### Phase 6：撰写分析

**每个主题下提取**：
- 典型引用（2-3条，标注受访者编号如P03）
- 支撑编码列表
- 与Step 1研究目标的关联说明
- 与其他数据源发现的交叉对照提示

**引用标注规范**：
- 使用受访者编号（如P01, P02），不使用真实姓名
- 引用保留原始措辞，不做改写
- 长引用可省略中间部分，用[...]标注


## 与其他嵌入框架的衔接

访谈数据是多种结构化框架的核心输入（详见 `references/frameworks.md`）：
- **用户画像**：访谈提取区分用户的行为/目标维度，形成画像假设
- **JTBD 动机映射**：访谈是任务陈述与动机的主要来源（8-20 人），提供"情境→动机→期望结果"三类证据
- **灵犀旅程**：访谈是驱动因素与典型问题的主要来源（8-20 人，旅程回溯）
- **心智模型**：访谈提取用户的"任务"陈述，聚合为任务塔
- **服务蓝图**：访谈提供顾客体验视角，与桌面/流程数据对照

当 Step 3 判定需要产出上述框架时，按 `references/frameworks.md` 对应章节执行。

## 备选方法：框架分析（Ritchie & Spencer）

当用户在Step 1提供了非常明确的研究问题和访谈提纲时，可考虑使用框架分析替代主题分析：

**区别**：
- 主题分析：自下而上，主题从数据中浮现
- 框架分析：半结构化，先有研究问题框架，再将数据填入框架

**框架分析步骤**：
1. 熟悉数据
2. 识别主题框架（基于研究问题+访谈提纲）
3. 索引：将数据片段标记到框架对应位置
4. 图表化：构建矩阵（行=受访者，列=主题），每格填入摘要
5. 映射解读：读列看主题横切面，读行看个体全貌

**选择标准**：如果用户的研究问题很清晰且访谈结构化程度高，用框架分析更高效透明；如果是探索性研究，用主题分析更灵活。
