# 研究类型定义与分析指引

> 本文件为用户研究分析结论技能的参考模块，在 Step 1 确定研究类型、Step 3 调整分析焦点、Step 4 综合聚类时读取使用。
> 本技能按"研究类型"组织分析与分析结论生成，共 8 类。研究类型描述"本次研究在回答什么性质的问题"，决定**分析覆盖面**（分析焦点、聚类主线、核心内容建议），而非分析结论的章节形式。一次研究可包含多种研究类型。

## 研究类型的确定方式

研究类型**从研究目的自动提炼**，用户无需手动输入，只需确认或修正：

1. Step 1 收集到"研究目的/要回答的问题"后，技能根据研究目的中的信号自动匹配一个或多个研究类型（信号词对照见下表）。
2. 将匹配结果展示给用户确认；边界情况（目的模糊、混合信号）主动追问。
3. 若用户从研究材料产出 Skill（**ux-kit**）衔接过来，可直接依据方案中的研究目标推断类型。
4. 用户也可手动增删研究类型（多选）。

**研究目的 → 研究类型 自动匹配信号**（依据研究目的与关键关注点中的表述）：

| 研究类型 | 研究目的中的典型信号 |
|---------|---------------------|
| 客群研究 | 某类客群有什么特点、用户画像、目标客群特征、分客群 |
| 用户需求分析 | 用户需要什么、深层需求、需求洞察、习惯与偏好的原因、动机、为什么、未被满足的需求、JTBD、用户现在怎么解决、任务视角 |
| 竞品分析 | 竞品、对标、借鉴、行业趋势、升级改版参考 |
| 需求分析 | 需求优先级、建设改造排序、需求取舍、卡诺 |
| 功能架构设计 | 功能如何分类、信息架构、功能组织、菜单结构 |
| 设计方案对比验证 | 方案对比、哪个方案更好、A/B方案、设计验证、是否符合需求 |
| 体验测试 | 是否达到上线标准、上线预备度、上线前测试、体验预测 |
| 体验评估 | 满意度、体验如何、体验水平、ETS、用户声音评估 |

## 研究类型总表

| 研究类型 | 研究问题 | 研究目标 | 研究方法（对应数据引擎） |
|---------|---------|---------|------------------------|
| 客群研究 | 某类客群有什么特点？ | 探索特定客群的特点（基本特征、行为习惯、态度偏好，生活/金融场景下的需求与痛点），为产品服务的创建及设计提供用户视角建议 | 深度访谈、焦点小组、灵犀旅程、日记法 → interview / user_voice |
| 用户需求分析 | 我们的用户需要什么样的产品？ | 深入挖掘形成用户习惯及态度偏好的原因，为产品设计、后续运营推广提供深层决策依据 | 访谈、问卷 → interview / questionnaire / user_voice |
| 竞品分析 | 竞品有何借鉴之处？ | 解析某产品/服务领域同异业相似产品的定位、功能组成、客群特点，为产品创建或升级改版提供未来发展趋势及机会点（含直接竞品、行业竞品、战略方向） | 桌面研究、服务蓝图、问卷 → questionnaire / analytics / interview |
| 需求分析 | 需求优先级如何？ | 梳理整合各类用户需求，依据需求类型和重要程度形成建设改造优先级 | 问卷（卡诺模型）→ questionnaire |
| 功能架构设计 | 功能如何分类？ | 确定功能架构应如何分类才能更符合用户认知与操作行为习惯 | 卡片分类、访谈 → interview / questionnaire |
| 设计方案对比验证 | 两个设计方案哪个更好？需求设计是否符合用户需求？ | 比较不同页面布局、业务流程、交互方式、视觉风格的方案，给出用户偏好结论，揭示内在原因，给出最佳解决方案 | 眼动测试、访谈等 → eyetracking / interview / usability |
| 体验测试 | 需求/产品设计/产品体验是否符合用户需求，是否具备上线标准？ | 产品/服务上线前进行整体体验水平预测，形成上线预备度结论，为是否上线提供决策依据 | 可用性评估、ETS-E → usability / questionnaire |
| 体验评估 | 我们的产品体验如何？ | 通过用户满意度测评，结合用户声音、典型问题等，评估产品/服务整体及分维度体验水平 | 问卷（ETS-U、ETS-E）、众测、用户声音 → questionnaire / user_voice / analytics |

> 各研究类型的**核心内容建议**见 `references/analysis_template.md` 的"按研究类型的核心内容建议"（半结构化，可按需裁剪）。

## 一次研究含多类型的处理

一次研究的研究目标往往覆盖多个研究类型（如"竞品分析 + 体验评估"合出综合分析结论，"客群研究 + 用户需求分析"合出综合分析结论）。处理规则：

- **研究类型是多选**：Step 1 收集的研究类型集合代表"本次研究要覆盖的分析范围"，不是分析结论的章节清单。

- **分析结论组织方式**（详见 `references/analysis_template.md`）：
  - **融合式**（推荐）：多类型共享同一份"核心结论"，按主题整合呈现；类型仅决定分析覆盖面。适合关联紧密的类型组合（如竞品分析 + 体验评估共同支撑产品改版）。
  - **分块式**：当各类型相对独立时，分析结论按类型分块呈现（每个类型一个模块），最后统一给出行动建议。
- **示例**：
  - 竞品分析 + 体验评估：竞品定位/功能对比结论 与 自身产品满意度/体验问题 分块或融合呈现，交叉点（"竞品的机会点是否对应自身痛点"）作为综合结论。
  - 客群研究 + 用户需求分析：客群画像作为需求分析的受众底座，画像结论直接支撑"为谁设计哪些功能"的需求清单。

## 各研究类型详情

### 1. 客群研究

- **分析主线**：客群画像 → 行为习惯与态度偏好 → 生活/金融场景需求与痛点 → 产品服务机会点
- **聚类主题示例**：客群基本特征、核心使用习惯、态度与价值观、场景化需求、痛点与未满足需求
- **综合侧重**：需求与痛点回落到具体生活/金融场景中呈现；结论面向"为谁做、做什么"的产品与服务创建
- **关键产出**：客群画像卡片、需求与痛点清单、机会点清单

### 2. 用户需求分析

- **分析主线**：用户习惯与态度 → 深层原因挖掘（动机视角） → 需求清单与分类 → 对产品设计与运营的建议
- **聚类主题示例**：使用习惯的成因、态度偏好的来源、动机与障碍、未被满足的需求、任务动机（功能/情感/社会三维度）
- **综合侧重**：不停留在"用户做了什么"，深挖"为什么形成这样的习惯和偏好"（动机与成因），提供设计/运营的深层决策依据
- **关键产出**：需求清单（含动机与成因）、设计/运营建议；当研究目的涉及深层动机（"为什么""动机""用户现在怎么解决"）时，可嵌入 **JTBD 动机映射框架**（见 `references/frameworks.md`），补充产出 JTBD 动机映射表与机会点清单

### 3. 竞品分析

- **分析主线**：竞品地图 → 定位对比 → 功能组成对比 → 客群特点对比 → 趋势与机会点
- **聚类主题示例**：产品定位差异、功能矩阵差异、客群画像差异、交互与体验差异、发展趋势与空白机会
- **综合侧重**：按"对比维度"而非数据源组织结论；机会点需结合自身产品定位给出借鉴建议
- **对比维度**：竞品范围含直接竞品、行业竞品、战略方向三个层次
- **关键产出**：竞品定位/功能/客群对比表、趋势与机会点清单、借鉴建议

### 4. 需求分析

- **分析主线**：需求梳理整合 → 需求类型划分（卡诺模型）→ 重要程度评估 → 建设改造优先级
- **聚类主题示例**：基本型需求（必备）、期望型需求（越多越好）、兴奋型需求（惊喜点）、无差异需求
- **综合侧重**：需求优先级 = 需求类型（卡诺分类）× 重要度 × 实现成本；形成可执行的改造排序
- **关键产出**：需求分类表、优先级排序表

### 5. 功能架构设计

- **分析主线**：卡片分类执行 → 分类结果聚合 → 用户心智模型 → 功能架构建议
- **聚类主题示例**：用户的自然分类习惯、跨组放置不一致的功能、命名歧义项、心智模型与现有架构差异
- **综合侧重**：以"用户如何认知功能"为准组织信息架构，而非按业务部门或技术口径
- **关键产出**：功能架构图建议、与现有架构差异对比、命名/分组调整建议

### 6. 设计方案对比验证

- **分析主线**：方案说明 → 分维度对比（布局/流程/交互/视觉）→ 偏好结论 → 内在原因 → 最佳方案
- **聚类主题示例**：布局理解度差异、任务流程效率差异、交互可达性差异、视觉吸引与负担差异
- **综合侧重**：同时回答"哪个更好"（偏好结论）与"为什么更好"（内在原因）；涉及需求验证时单独给出"是否符合需求"的结论
- **对比型三角验证**：比较对象是不同方案而非不同数据源，需在方案间交叉（详见 `references/synthesis.md`）
- **关键产出**：分维度对比表、偏好结论与原因、最佳方案建议

### 7. 体验测试

- **分析主线**：测试执行概况 → 体验水平评估（可用性 + ETS-E）→ 问题清单与严重度 → 上线预备度结论
- **聚类主题示例**：阻断性问题、严重体验问题、一般问题、建议优化项
- **综合侧重**：结论落到"是否达到上线标准"这一决策上；问题按严重程度分级并区分"上线前必须修复"与"可后续优化"
- **关键产出**：上线预备度结论（达标/有条件达标/不达标）、必须修复问题清单

### 8. 体验评估

- **分析主线**：整体体验水平（ETS-U）→ 分维度评估 → 用户声音与典型问题 → 洞察与改进建议
- **聚类主题示例**：整体满意度、8 维度表现、典型痛点主题、分客群差异
- **综合侧重**：定量评分（ETS-U/ETS-E）+ 定性声音（用户声音/访谈）+ 行为数据（埋点）三线互证；与历史期或行业基准对比
- **关键产出**：整体与分维度评分、典型问题主题、改进建议优先级

## 研究类型与单/多数据源的关系

- 研究类型与数据源数量是两个独立维度，可任意组合：
  - 体验评估既可为"多源"（问卷 ETS-U + 用户声音 + 埋点），也可为"单源"（仅问卷 ETS-U）
  - 竞品分析可为"多源"（多竞品 × 多方法），也可为"单源"（单竞品桌面研究）
- 单/多源适配规则（见 `SKILL.md`）在任一研究类型下均适用；多源时执行三角验证与言行矛盾检测（分析阶段内部动作），单源时弱化跨源步骤。
